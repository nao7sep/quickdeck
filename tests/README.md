# QuickDeck's areas, and the tests that stand for them

`npm test` is the type check plus this whole Vitest suite, plus `cargo test`: at a few seconds it is
already a fixed, balanced run, so nothing selects a subset of it. This file is the balance judgement
the `tests-folder-conventions` require — which areas QuickDeck has, and which tests stand for each —
so a reader can tell what a green run covered, and an area with no test standing for it is visible
rather than merely absent. `tests/area-map.test.ts` holds every path below to what is on disk.

Paths are relative to the repository root, because QuickDeck's tests live in two trees: `tests/` for
the frontend and `src-tauri/tests/` for the Rust core.

QuickDeck has no paid, external, or heavy tests — no network, no provider, no large download — so
there is no separate `test:full`: `npm test` is also the full gate.

| Area | What it covers | Tests standing for it |
|---|---|---|

| Text, counts, and cleanup | What a pane's text is measured and normalized by: word, character, and X/Twitter-weighted counts, the single-line cleanup a pane title commits through, and the multiline and truncating cleanup snapshot bodies and excerpts go through. | `tests/utils/counts.test.ts`, `tests/utils/textCleanup.test.ts` |
| Autosave and the persisted store | The store QuickDeck writes to and reads back: first-run materialization, how a save that races another resolves, how a persistence failure is presented, and the data directory's on-disk file names kept separate per kind. | `tests/utils/saveRace.test.ts`, `tests/state/app-state-startup.test.tsx`, `src-tauri/tests/storage_file_names.rs` |
| Recovery snapshots | The SQLite snapshot history and its browser: listing newest-first, paging, narrowing by search, the detail pane, selection as rows change, timestamp display in local time, failure presentation, and the split's two independently scrolling halves. | `tests/components/SnapshotsModal.test.tsx`, `tests/utils/snapshotSelection.test.ts`, `tests/utils/snapshotTimestamp.test.ts`, `tests/styles/snapshotScroll.test.ts` |
| Settings, bounds, and zoom | The settings a user edits and the shapes they are held to: draft validation agreeing with clamping, normalization of settings and panes read back from disk, the settings modal, and the zoom ladder with its 50-500% bounds. | `tests/state/normalize.test.ts`, `tests/components/SettingsModal.test.tsx`, `tests/utils/zoom.test.ts` |
| Keyboard shortcuts and text entry | The chord vocabulary and its dispatch: chord matching, the definitions registry, chords that would shadow macOS text editing or a printable layout key, IME composition guards that keep a chord from firing mid-composition, and the shortcuts help modal. | `tests/shortcuts.test.ts`, `tests/utils/shortcuts.test.ts`, `tests/hooks/useComposing.test.ts`, `tests/components/ShortcutsModal.test.tsx` |
| Modals and focus | The modal layer every dialog is built on: the stack that tracks what is open, focus trapping and initial focus, the background scroll lock, and the About dialog's links. | `tests/modalStack.test.ts`, `tests/focusTrap.test.ts`, `tests/scrollLock.test.ts`, `tests/components/AboutModal.test.tsx` |
| Composite controls and scrolling | The shared interaction primitives the lists, tab bars, and menus are made of: roving index navigation, passive scroll regions driven from the keyboard, the one shared control height, and global scrollbar styling. | `tests/utils/compositeNav.test.ts`, `tests/utils/passive-scroll.test.ts`, `tests/styles/controlHeight.test.ts`, `tests/styles/scrollbar.test.ts` |
| Notifications and toasts | What the app tells the user about an operation: which layer owns an operational toast, the toast list and its dismissal, lifetime policy, and a viewport that stays reachable rather than covering what it reports on. | `tests/state/toasts.test.tsx`, `tests/components/ToastViewport.test.tsx`, `tests/utils/toastPolicy.test.ts`, `tests/styles/toastViewport.test.ts` |
| Interface text and localization | The text QuickDeck shows in ten languages: catalogue completeness and placeholder and plural agreement, the translator, language preference resolution and formatting locale, the scan for text written straight into JSX, and the languages the macOS bundle declares so AppKit draws its own menu items in the right one. | `tests/i18n/catalogues.test.ts`, `tests/i18n/translate.test.ts`, `tests/i18n/languages.test.ts`, `tests/i18n/hardcoded-text.test.ts`, `tests/config/bundle-localizations.test.ts` |
| Theme and window chrome | Light and dark following the system: preference resolution on both sides of the boundary, the saved theme read from config, token contrast on the surfaces the stylesheet places them on, the native window background and title bar, and the window results the app applies at runtime. | `tests/utils/theme.test.ts`, `tests/styles/themeContrast.test.ts`, `tests/styles/windowChrome.test.ts`, `tests/App.test.tsx`, `src-tauri/tests/theme.rs` |
| Window placement and sizing | Where the window comes back: the normal rectangle retained across a maximized, minimized, or fullscreen close, the minimum width and height derived from the pane count, and the window-state plugin wiring that restores it. | `src-tauri/tests/window_placement.rs`, `tests/utils/layoutMetrics.test.ts`, `tests/config/tauri-window-state.test.ts` |
| Errors, logging, and recovery | What happens when something fails: the log event and serialized error shapes, the console object they render to, and the root boundary that keeps a render failure from leaving a blank window. | `tests/services/logger.test.ts`, `tests/components/RootErrorBoundary.test.tsx` |
| The security boundary | The line between the WebView and the machine: the production Content-Security-Policy, the external drag-and-drop transport the manifest enables and the renderer boundary that accepts a drop, and the development endpoint pinned to one app-owned loopback port. | `tests/security/csp.test.ts`, `tests/config/tauri-drag-drop.test.ts`, `tests/utils/external-drop-boundary.test.ts`, `tests/config/development-endpoints.test.ts` |
| Packaging, versioning, and licensing | What ships and what it says it is: one version across every manifest and the parsers that read them, the installer configuration, the Cargo development build policy, the double-clickable launchers' process identity, and the third-party notices packaged as a resource. | `tests/version.test.ts`, `tests/helpers/versions.test.ts`, `tests/installer-config.test.ts`, `tests/config/cargo-development-profile.test.ts`, `tests/config/launcher-runtime.test.ts`, `tests/config/third-party-notices.test.ts` |
| This map | The balance judgement above, held to what is on disk so a rename or a deletion breaks the run instead of quietly hollowing out the map. | `tests/area-map.test.ts` |
